# Enable Banking research

Researched on 2026-11-09 from Enable Banking's documentation and the open-source clients that use it, for the backend's Enable Banking client.
Move each fact into the code that handles it, and delete this note once none remain.

## Authentication

- Every request carries `Authorization: Bearer <JWT>`, signed RS256 with the application's private key, with header `{typ: "JWT", alg: "RS256", kid: <application ID>}` and claims `{iss: "enablebanking.com", aud: "api.enablebanking.com", iat, exp}` ([API reference][ref], [quick start][qs]).
- A token is valid for at most 86,400 seconds and reaches every consent of the application, so the token and the private key never leave the backend ([FAQ][faq]).
- The Control Panel can generate the key pair in the browser and download the private key as `<application-id>.pem` ([Control Panel][cp]).
- In restricted mode the API returns only accounts linked in the Control Panel and strips all others from responses, and linking still requires the consent flow below ([linked accounts][linked], [FAQ][faq]).

## Consent flow

The [consent flow](../architecture.md#consent) maps to these calls ([API reference][ref], [quick start][qs]):

1. `GET /aspsps?country=DE` lists the banks with their `maximum_consent_validity` and `required_psu_headers`.
2. `POST /auth` with `access.valid_until`, `aspsp {name, country}`, `state`, `redirect_url` and `psu_type: "personal"` returns the authorization `url`.
3. The user accepts Enable Banking's end-user terms and logs in at the bank, which returns the browser to `redirect_url?code=…&state=…`.
4. `POST /sessions {code}` returns a `session_id` and the linked accounts, each with a `uid` and an `identification_hash`.

- A `valid_until` later than now plus `maximum_consent_validity` seconds fails with 422; computing it in calendar days across a daylight-saving change triggered exactly that ([Firefly III #12553][ff-12553]).
- A consent cannot be refreshed: after expiry the user authorizes again, and `EXPIRED_SESSION` can arrive early, for example at banks that allow only one active consent per user ([FAQ][faq]).
- An account's `uid` changes with every consent, while its `identification_hash` stays stable across consents ([FAQ][faq]).
- Deutsche Bank asks for the Deutsche Bank ID before the redirect; `POST /auth` can pass it in `credentials`, or the user types it during authorization ([Germany notes][de], [API reference][ref]).
- Production redirect URLs must use HTTPS, rejecting `http://localhost` and `app://`, while open-source clients register `https://localhost:<port>/callback` ([MoneyMatter #773][mm-773], [Actual Budget docs][ab-docs], [beancount-enablebanking][beancount-eb]).
- Enable Banking never calls the redirect URL, since only the browser follows it, so the callback need not be public ([Firefly III docs][ff-docs]).

## Fetching transactions

- `GET /accounts/{uid}/transactions` takes `date_from`, `date_to`, `transaction_status`, `strategy` and `continuation_key` ([API reference][ref]).
- Full history is usually available only within about one hour after authorization, so the first fetch uses `strategy=longest` ([FAQ][faq]).
- History older than 90 days may need an extra SCA, requested through `access.transactions_extended_history`, which defaults to `true` ([API reference][ref]).
- Page sizes vary, an empty page that carries a `continuation_key` means "keep going", and every other parameter must stay identical across pages ([FAQ][faq]).
- A bank can repeat its `continuation_key`: Trade Republic returned the same key with the same 100 transactions, so the client stops on a repeated key before appending the page ([Actual Budget #9046][ab-9046]).
- Many banks allow 4 unattended fetches a day and answer 429 `ASPSP_RATE_LIMIT_EXCEEDED` beyond that, which Enable Banking advises retrying after 6 hours ([FAQ][faq]).
- Sending the PSU headers a bank requires, such as `Psu-Ip-Address` and `Psu-User-Agent`, marks a fetch as user-started and lifts that cap; a request sends all of them or none, else it fails with 422 `PSU_HEADER_NOT_PROVIDED` ([FAQ][faq]).
- Whether banks accept a private network address in `Psu-Ip-Address` is untested.
- Account data is available by polling only, because webhooks cover payment status alone ([webhooks][webhooks]).

## Transaction fields

The fields that matter, from the [API reference][ref] and the [FAQ][faq]:

| Field | Meaning |
| --- | --- |
| `entry_reference` | the bank's transaction ID, unique and immutable only within one account; usually present for booked transactions only, missing at some banks, duplicated at others, and sometimes generated by Enable Banking |
| `transaction_id` | a handle for fetching details that may change between fetches and identifies nothing |
| `booking_date`, `value_date`, `transaction_date` | all optional; `transaction_date` is the card, transfer or direct-debit date |
| `transaction_amount` | required decimal string with an ISO 4217 currency; the sign comes from `credit_debit_indicator` (`CRDT` or `DBIT`) |
| `creditor`, `debtor`, `creditor_account`, `debtor_account` | optional counterparty name and account |
| `remittance_information` | optional array of strings |
| `status` | required: `BOOK`, `PDNG`, `HOLD`, `SCHD`, `CNCL`, `RJCT` or `OTHR` |

- Some banks reuse `entry_reference` across accounts, for example as a per-day index ([Firefly III #13115][ff-13115]).
- Some banks change `entry_reference` when a pending transaction books ([Firefly III #11925][ff-11925]).

## Bank quirks

- ING's purpose text arrives as one string `mandatereference:…,creditorid:…,remittanceinformation:…`, from which `remittanceinformation:(.*)$` recovers the free text ([Firefly III #12811][ff-12811], [Actual Budget ING handler][ab-gc-ing]).
- ING lists future transactions 5 days to 2 weeks ahead with fixed dates, which a `transaction_status=BOOK` filter presumably excludes ([BankingSync #9][bs-9]).
- Enable Banking moved ING to ING's API v4 in September 2026, after both ING reports above, so either may have changed ([changelog][cl-2026-09]).
- ING requires `Psu-Ip-Address` whenever any PSU header is sent ([bank list][aspsps]).
- PayPal leaves `booking_date`, `value_date` and `remittance_information` empty, so `transaction_date` is its only date ([Sure #1193][sure-1193]).
- PayPal delivers a foreign-currency purchase in its original currency only, without the euro amount charged ([Firefly III #13163][ff-13163]).
- PayPal returns one balance entry per currency, zero balances included ([Sure #4076][sure-4076]).
- PayPal returns no accounts until they are linked ([Actual Budget #7799][ab-pp-link]).
- Deutsche Bank is in beta at Enable Banking, and no field-level reports exist ([bank list][aspsps]).

## Client

- No official SDK exists, but the OpenAPI 3.1 spec can generate TypeScript types ([spec][yaml]).
- Actual Budget's Enable Banking server is a working TypeScript client with JWT signing, paging guards and derived IDs ([source][ab-src]).
- The API carries no version in its path or headers, and its changes so far were additive ([spec][yaml], [FAQ][faq]).
